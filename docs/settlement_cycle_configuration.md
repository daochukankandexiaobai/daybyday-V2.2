# 结算周期配置说明

## 默认规则

新建数据库默认使用自然月结算：每月 1 日至当月最后一天。

例如，2026 年 7 月的结算周期为 `2026-07期`，范围为
`2026-07-01 ~ 2026-07-31`。

## 管理员配置

管理员登录后，在“系统设置”的“结算周期规则”区域可以：

1. 保持自然月结算；或
2. 在尚未录入日报、周目标、周期目标时，设置每月 1 至 28 日中的任意一天为周期起始日。

自定义周期仍按结束月命名。例如起始日设为 5 日时：

- `2026-07-05 ~ 2026-08-04` 显示为 `2026-08期`。

设置完成后应使用“确认并锁定”。锁定后，应用内不允许直接改动初始规则。

## 历史数据保护

已有日报、周目标或周期目标的数据库会自动保留历史兼容规则并锁定。迁移不会重写已有
`daily_records.settlement_cycle_code`，也不会删除或调整历史日报、周目标、导入日志或导出记录。

## 后续变更规则

已有业务数据后，不应直接修改初始规则。请在“后续规则（按生效日期）”区域新增一条规则：

1. 选择新规则，例如“自然月”；
2. 选择新规则的第一个周期起始日，例如 `2026-09-01`；
3. 点击“新增未来规则”并确认；
4. 从该日期起，新的日报、周目标和周期目标使用新规则；该日期之前的数据继续使用历史规则。

相邻规则可能产生相同的周期显示名。例如旧规则的最后一段和自然月的第一个周期都可能显示
为 `2026-08期`。系统会同时保存规则快照，因此日报、周目标、周期目标和统计不会相互混淆。

## 在新设备导入历史备份

若要在新设备上使用自然月，同时保留旧设备按“29日至次月28日”保存的历史数据，推荐顺序如下：

1. 安装新版程序并打开“系统设置”；
2. 在“后续规则（按生效日期）”中选择“自然月”；
3. 将生效日期设为历史备份最后一条日报之后的某个每月 1 日；
4. 点击“新增未来规则”；
5. 再通过 JSON 导入旧备份。

导入时，旧 JSON 中保存的结算周期代码和规则快照会一并保留。旧 JSON 没有规则快照时，系统会
识别传统“29日至次月28日”的周期边界并按历史兼容规则导入。不要通过“保存周期规则”去重写
已有历史规则。
